### [0:25 – 0:55] The Maintainer Problem (Slide 2)
*(Slide 2 visible on projector)*

"In open source today, reviewing code has become an overwhelming bottleneck. 

Just this month, the Linux Foundation published research showing that 25% of incoming pull requests are considered low-effort 'AI slop'. These are pull requests generated by LLMs with beautiful Markdown descriptions, but code that does nothing or quietly breaks features. Even curl had to suspend its bug bounty program over this exact issue.

Here is the fundamental blindspot: GitHub only shows you what lines of text changed in a diff. But code doesn't live in isolation. A two-line change in an internal utility can quietly break five critical modules and test suites across the repository. Maintainers don't need another list of lines. They need to understand what those lines affect, and what deserves attention first."

### [0:55 – 1:30] How Sieve Works (Slide 3)
*(Slide 3 visible on projector)*

"Sieve takes a completely different, evidence-based approach through five simple steps:

1. **Connect:** Our Chrome extension attaches to GitHub in 100% read-only mode — no write tokens required.
2. **Understand:** Our Python engine uses standard-library AST to parse the repository into an internal import topology.
3. **Analyse:** We verify contributor claims: did they link a real open issue? Are claimed tests actually in the diff? Do imported modules exist?
4. **Identify Risks:** We map the exact blast radius DAG: modified files, direct dependents, and regression radars.
5. **Guide Action:** We present clear triage lanes, exact pytest reproduction commands, and polite contributor checklists.

Crucially: we never mix up code facts with AI hallucinations. Deterministic AST facts are 100% verified. When Google's open-weight Gemma 4 multimodal model reasons over the visual architecture, its output is strictly tagged as model hypothesis."

### [3:00 – 5:00] Anticipated Q&A Cheat Sheet for Judges

**Q: "Isn't this just CodeRabbit or GitHub Copilot review?"**
> **A:** "No. CodeRabbit and Copilot are hosted SaaS bots that review code line-by-line using hosted LLMs and bill per pull request. They also post comments directly onto contributor PRs. Sieve is a local-first maintainer workspace. It checks whether contributor claims hold against repository reality, calculates blast radius through deterministic AST import graphs, labels every finding's source, runs open-weight models locally, and is 100% read-only."

**Q: "What if the AI model makes a mistake?"**
> **A:** "Our architecture was designed specifically for that. The blast radius, import verification, file checks, and regression radar are 100% deterministic Python AST code — zero AI, zero hallucinations. The Gemma 4 model is only used for high-level architectural interpretation, and every statement it makes is badged as a model hypothesis. The maintainer always has the deterministic facts first."

**Q: "Does Sieve run the contributor's code or tests?"**
> **A:** "Never. Running untrusted contributor code on a maintainer's machine or server is a major security risk. Sieve parses the code statically via AST. Instead of running tests, Sieve gives the maintainer the exact pytest command so they can run it safely in their own verified CI sandbox."

**Q: "What languages are supported?"**
> **A:** "Full AST import graphs and regression radar are implemented for Python and JavaScript/TypeScript today. All claim verification, template checks, issue linking, diff statistics, and lifecycle queues are completely language-agnostic."
